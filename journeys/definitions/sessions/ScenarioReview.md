Current analysis is awaited after position changes and restoration before payload comparisons, independently of immutable actual-move records.

## Usability observations and limits

The composed tasks exercise visible controls, mode labels, persisted actual-move records, return actions, snapshot details and recoverable write feedback. Duplicate loaded/imported games retain their display name; the library presents separate groups without a visible identity label. The library session selects the original first tab and uses its current-group selection to disambiguate those copies, then verifies the route ID. Home shows only three recent cards, with View all for the complete library; the session explicitly reopens the newest imported copy after creating six identities. These are concrete discoverability observations for the later JRN-UX work, linked to [Q-UX-001](../../../docs/questions/usability/Q-UX-001-UsabilityReference.md), rather than new acceptance rules or a claim of reference-site parity. Browser automation does not establish manual ease of use, keyboard/focus acceptance, small-screen acceptance or native NW.js behaviour.

Execution evidence is recorded in [JourneyImplementation.md](../../../docs/JourneyImplementation.md#complete-session-verification). The broader payload/replacement, live-progression and reference-task questions remain review prompts; none changes these settled functional assertions.
