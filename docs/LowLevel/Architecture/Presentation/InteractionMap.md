# Presentation interaction map

This map records the implemented Vue surfaces and their action owners. Views compose routes and retain shared workflow resources; feature components render their own markup, read store data directly and handle complete local interactions. Common components and the modal shell retain their drawing and dialog contracts, and all styling comes from the global CSS entry. See [Presentation Architecture](index.md#markup-and-ownership-rules) for why there is no separate generic render layer.

| Surface | Local owner and store calls | Retained boundary |
| --- | --- | --- |
| Home quick game | `useQuickGame` validates accepted defaults, checks required engine players, awaits `createGame`, opens the tab and navigates, with owned busy/error state and route/lifecycle cancellation. | `MenuBar` uses the same action. A quick-game error offers *Edit game defaults*. |
| Custom creation and setup | `GameCreationModal` owns the form, validation, engine readiness checks and `createGame` / `startGameFromSetup` submission. | `dismissed` closes the captured opening. `GameView` retains the Menu-pause completion for custom creation started from the game menu. |
| Recent and library selection | `HomeView` and `SavedGamesView` coordinate `RecentGameStore` / `SavedGamesStore` loading, `GamesStore.insertGame`, `UiStateStore.openTab` and navigation. | Library confirmations keep their captured target owners. |
| Menu quick game and close | `MenuBar` uses `useQuickGame` and `useGameTabActions.close`; `gameId` decides save and close availability. | Home, Custom, Load, Save and Settings emit events into `GameView`'s playback and Menu-pause workflow. |
| Game tabs | `GameTabs` reads session membership, game names and the committed route; select and close use `useGameTabActions`. | The App route checkpoint publishes a successful selection. Close clears only the target game's premoves before removing the tab; switching preserves queues. Games and saved files survive tab close. |
| Board input | `Chessboard` owns selection, drag, touch tap, the board-edit palette and the promotion gesture. | `moveAttempted` and `premovesCancelled` reach `GameView`'s captured rendered-board owner. Five board-edit events target the displayed game through guarded `GamesStore` actions. |
| History | `HistoryPanel` reads the reactive tree and paths, owns its saved fold and resolves row, Start and Live position targets. | `nodeSelected` enters `GameView._navigateToNode`, which cancels playback and continuation before store navigation. |
| Move stepping | `GameControlPanel` resolves First, Previous, Next and Last along the mainline in analysis, study and review modes. | Emits the same `nodeSelected` into `GameView._navigateToNode`. |
| Analysis management | `AnalysisPanel` reads canonical seats and settings and owns folds, refresh, retry, stop, add and remove. Removal reconciles its fold entry. | `moveSelected` keeps the stable raw PV references and enters `GameView`'s due-turn, off-turn or exploratory routing. |
| Analysis line preview | `ExpandableText` truncates a PV line and opens a popover containing the individual move buttons. | The move buttons still emit through `AnalysisPanel.moveSelected`. |
| Player strip | `PlayerPanel` reads its colour's seat and opens `PlayerSelectionModal` itself. | `GameView` supplies the shared clock, active-turn and captured-material projections and the playback lock. |
| Controls | `GameControlPanel` owns manual pause and resume, board-edit entry and finish, setup start, resignation and draw negotiation through public `GamesStore` methods. | Takeback and analysis entry/exit emit into `GameView`'s captured input owner. The paused-state Analyse / Exit analysis button is rendered by `GameView` and calls the same actions. |
| Game end | `GameView`'s clock tick reconciles an expired clock and consumes the one-shot result notification by opening `GameResultModal`. | The modal's Exit uses `useGameTabActions.close`; Save for analysis navigates to the save route; Start analysis awaits `refreshAnalysis`. |
| Settings | `SettingsView` owns the draft form, Apply/Save/Cancel, reset and dirty-leave confirmation, and the engine overview. | Successful Apply, Save or Reset emits `appearanceChanged` to `App`. |
| Engine profiles and packages | `EngineProfileView`, `EnginePackageImportView` and `EnginePackageDetailsView` are routed children of Settings; each owns its form, file action and lifecycle. | Profile edits change only the Settings draft; package import and removal change browser files immediately. |
| Navigation drawer | `NavigationFrame` owns desktop expansion and opens `NavigationMenuModal`, which renders the same brand, action and footer slot closures. | The modal provider owns the drawer opening's dismissal and focus cleanup. |

`GameView` retains one clock timer, the game-end notice, the rendered canonical and premove board snapshot, the playback `OperationOwner`, the pending historical continuation, Menu interruption and route activation. It does not forward player, seat, tree, fold or independent control actions. All mutations still cross existing store or domain boundaries; no rule, engine-resource or persistence implementation moves into a component.

Premove `displayPosition` remains distinct from the canonical `position`. The premove endpoint set and the eligible local colour drive artwork, cancellation and candidate selection. Board and PV input keep their raw entries: on a local due turn PV selection submits the first move; on an eligible off-turn it submits only the clicked local candidate after parity and projected-geometry checks; explicit, free and result analysis plays the selected canonical prefix. No opponent replies are queued from a PV.

Panels read reactive fields and arrays, including in-place history and seat changes, without a revision prop or clock tick. They save their own fold actions through `UiStateStore` and show local failures. A genuine pause blocks gameplay input but keeps analysis management, folds and player reassignment available; explicit paused analysis keeps its exploration permissions; board edit blocks engine startup and player changes.

[Shared dialog flows](SharedDialogFlows.md) records the modal provider, local form submission, captured confirmations, draw response, promotion, game result and mobile navigation. The modal action helper prevents duplicate starts and suppresses late UI errors and dismissal; it does not dispatch commands or own a global current dialog. Existing domain work keeps its completion semantics.
